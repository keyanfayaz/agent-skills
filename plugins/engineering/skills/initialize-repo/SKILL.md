# Initialize repo

1. Read the project instructions and check the Git root and any existing remotes. Confirm the intended root if the project sits inside another repo and the scope is unclear. Initialize Git if needed and follow any established branch naming convention.
2. Add project-specific ignore rules as needed. Before the first commit, review what's staged for local secrets, dependencies, and build output.
3. For a starter README, adapt the [app template](assets/app-readme.md) or the [tool and skill collection template](assets/tool-readme.md). Use the project's actual commands and structure, keep useful existing content, and omit sections that add no information.
4. When GitHub setup is requested, connect the specified repo or create one once the owner, name, and visibility are clear. When publishing, check the destination, verify the first push, and report the repo URL.
