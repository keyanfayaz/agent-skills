# Plan a project

- Start with the user's goal, constraints, existing tracker, and supplied project context; ask only for missing details that materially affect the plan.
- Define the outcome and how completion will be recognized, then identify a small set of milestones and next actions.
- Use [the project template](assets/project.md) as needed; omit empty sections and keep each action concrete.
- Record known owners and dates; label unknowns instead of inventing commitments.
- Keep plans in the project's existing home; project-specific facts belong beside the project, not in the reusable plugin.
- Follow the user's writing preferences and explicit request; preserve meaningful existing tasks when revising a plan.
- Save to a tracker or contact anyone only within the authorized task scope.
